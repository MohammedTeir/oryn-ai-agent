# Milestone 1 navigation scaffold

An independent, non-executing application shell entry exists at `../production/index.ts`. Run `node scripts/bundle-production.cjs` from the spike directory to bundle it. Its import graph does not include the feasibility app, preview approval example or native probe module. The feasibility APK still starts the test harness and now offers a clearly labeled **Open local app shell preview** button, alongside the existing navigation preview. The APK itself still contains the feasibility native module and test controls; it is debug-signed and is not a production APK. The shell loads the shared locally stored language preference and offers language selection in Settings; unavailable screens and the connection state remain truthful placeholders. Branding approval, production startup/integration, full accessibility and device testing remain open.

`bash scripts/build-shell-test.sh` builds a separate, debug-signed arm64 shell test APK in an isolated temporary project and writes it to `artifacts/oryn-shell-test.apk`. It checks the APK signature, JS entry markers, known feasibility native classes and probe binary, Termux execution permission, and SecureStore backup exclusions. The Android workflow uploads it as a separate action artifact; the existing GitHub prerelease continues to publish the feasibility APK. This test APK uses the same owner-authorized **debug-only** application ID as the feasibility APK. Installing it may replace that app or fail if signatures differ; installation and data migration have not been tested. A production application ID, production signing and release packaging remain undecided.

The shell's AI Agent view opens the most recently updated local conversation and allows choosing another saved conversation or starting a new one and displays saved user messages in pages of up to 100, with Previous and Next controls. Pages are not snapshots: concurrent changes may require a refresh, and a full last page can lead to an empty next page. The local-only composer saves user text without Gemini or execution. A pending local save is staged in SQLite before writing; on app startup the shell checks for interrupted work and asks the user to check, retry or explicitly discard it. Unknown outcomes block new saves. The flow has not been verified after Android process death. Empty, loading and failure states are distinct. The production shell has not been installed or tested on a device.

This separate entry provides the two primary destinations, secondary Settings, and the Terminal / Tools / History segments. Screens contain unavailable placeholders; they do not execute commands or report simulated connection state. The existing feasibility entry and native gateway are unchanged.

`node scripts/bundle-milestone1.cjs` checks that Metro can bundle this entry. The feasibility APK opens the test harness and includes an explicitly labeled navigation preview, with a return button. The harness remains mounted while the preview is open so its captured in-memory evidence is retained. This does not establish device behavior; phone verification is outstanding.

The header uses the approved symbol and the product name as system text. An approved standalone wordmark without the tagline is not present in the supplied PNG assets, so the specified branded wordmark remains unresolved. Exact icon sizing and the Arabic font are also unknown. Verify the layout, scaling, RTL, accessibility, and tab symbol on a device before considering this scaffold finished.

The AI Agent navigation preview includes an explicitly labeled approval-card example with disabled decision controls. It contains illustrative data only, has no execution or authorization callback, and is not a production proposal component. Real proposal binding, complete Batch/Session scope review, native-gateway integration, separate high-risk confirmation, and device accessibility/RTL testing remain outstanding.
